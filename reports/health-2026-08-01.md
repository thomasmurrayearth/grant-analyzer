### The permanent fix: snapshots committed by CI

The root cause of both blind cycles was one thing: **the reviewer depended on
making a live, authenticated network call at the moment of review.** Cycle 1
lost that call to a paused database, cycle 2 to an unreachable endpoint. So the
call was removed from the review entirely.

`.github/workflows/quality-snapshot.yml` runs daily at 07:00 UTC, reads
`ADMIN_TOKEN` from GitHub Actions secrets, fetches `/admin/quality.json` and
`/health?deep=1`, and commits `reports/snapshots/quality-YYYY-MM-DD.json`. The
review reads a file. No network, no token, no secret in any prompt.

This is the ordinary way scheduled reporting is done. Nothing about it is
novel, which is the argument for it.

Three properties earn their place:

| Property | Why it matters here |
|---|---|
| **A failed fetch is still committed**, with its HTTP status and the unauthenticated health payload | A missing file and a broken database used to look identical. Now an outage is data and the day it started is visible. |
| **The job commits daily**, and a commit is the only thing GitHub counts as activity against its 60-day auto-disable rule for scheduled workflows | The mechanism cannot be switched off by the quiet fortnights it exists to cover — exactly the trap cycle 1 fell into, where the app being quiet was also what broke the measurement. |
| **A bad snapshot exits non-zero**, so GitHub emails the owner | This is the alarm that was missing both times measurement died silently. |

Git history also becomes the archive: every day is a commit, so any past date
can be reconstructed, and a lost cycle can be recovered rather than gone.

| Artefact | What it is |
|---|---|
| `.github/workflows/quality-snapshot.yml` | The daily job. All three shell paths (200, 503, app down) verified offline to emit valid JSON. |
| `snapshots.py` | Offline read library — `health_report()`, `staleness_days()`, `series()`, `movement()`. Pure, no network. |
| `eval/read_snapshots.py` | CLI. Prints pipeline health first, then headlines and trends. **Exits non-zero when blind.** |
| `tests/test_snapshots.py` | 31 tests, mostly about *not* measuring: stale files, missing days, failed fetches, corrupt JSON. |
| `reports/snapshots/README.md` | Why the folder exists, the file shape, and the one rule. |
| `LAUNCH_SETUP.md` §3 | The one-time GitHub secret step. |

**Staleness is treated as the primary hazard.** A cycle quoting a three-week-old
snapshot as current is worse than one reporting nothing, because it manufactures
confidence. So `read_snapshots.py` leads with freshness, prints a blunt warning,
and exits non-zero — a blind cycle is now caught in the first thirty seconds
rather than after an hour.

**One action is required from Thomas:** add `ADMIN_TOKEN` as a GitHub repository
secret. Until then the workflow runs and fails every morning — loudly, by email,
which is the correct behaviour.

### Also removed: the results email

Not plumbing, but it came out of the same investigation and Thomas instructed
the removal. The landing page promised *"Email me my results when they're ready
— you can safely lock your screen."* The app has never sent a single message:
`RESEND_API_KEY` and `RESEND_FROM_EMAIL` were never set in Railway, were never
listed in `LAUNCH_SETUP.md` among the variables to set, and the send path
returned silently when either was missing — the same swallow-the-failure pattern
that hid the database outage for a fortnight.

Anyone who left an address and locked their phone got nothing back, and no
metric would ever have shown it.

Results appear in the page; web push is configured, works, and is now the only
notification promise made. The address field remains for the grant-deadline
digest only, and the address is stored **only** when that consent is given —
with results delivery gone, an address typed without ticking the box has no
purpose to be kept for. Capacity and waitlist copy now promise a human getting
in touch. `tests/test_app.py` gains a `NoResultsEmailTest` class so the promise
cannot return by accident.

**218 tests green**, up from 187.
